# auto-time-report

Telegram-бот, который списывает отработанное время в Jira (WorklogPRO) из недельного поста в Telegram-канале и отправляет таймшит на проверку.

> Статус: MVP собран целиком и проверен тестами и в Docker. Боевой прогон против настоящих Jira и VPN ещё впереди.

## Как это работает

1. В понедельник создаёшь в канале один пост на неделю и каждый день дописываешь в него новый день.
2. Бот (админ канала) видит каждую правку и сразу пишет в личку, если нашёл ошибку в формате или ты поменял день, который уже записан в Jira.
3. По рабочим вечерам бот напоминает, если за сегодня нет записей. В пятницу присылает превью недели с кнопками (или по команде `/submit`).
4. Жмёшь "Записать" или "Записать и на проверку", бот просит пароль-фразу и сразу удаляет сообщение с ней.
5. Бот расшифровывает доступы, поднимает VPN (приходит **один** пуш Multifactor), записывает worklog'и, при необходимости отправляет период на проверку, гасит VPN и присылает итог со ссылкой на календарь.

Почему пароль-фраза и как устроена защита доступов - в [docs/security.md](docs/security.md). Разбор API Jira и WorklogPRO - в [docs/jira-api.md](docs/jira-api.md).

## Формат поста

### Одна задача

Если все часы идут в одну задачу, строку-задачу писать не нужно: записи уходят в `JIRA_DEFAULT_ISSUE_KEY`.

```
19.10
XYZ-101: Ревью контрактов - 2 часа
XYZ-102: Правка путей proto-модулей - реализация - 6 часов

20.10
XYZ-103: Справочник типов карт - реализация - 7 часов 30 минут
Созвон по архитектуре - 30 минут
```

### Несколько задач

Строка, в которой стоит только ключ задачи, задаёт, куда пойдут записи ниже. Задача действует до следующей строки-задачи, через любые даты.

```
ABC-1
19.10
XYZ-101: Ревью контрактов - 2 часа
XYZ-102: Правка путей proto-модулей - 4 часа

20.10
XYZ-103: Справочник типов карт - 8 часов

ABC-2
19.10
Онбординг нового разработчика - 2 часа
```

Здесь 19.10 даёт два worklog'а: 6 часов в `ABC-1` и 2 часа в `ABC-2`, всего за день 8 часов.

### Правила

| Строка | Как выглядит | Что значит |
|---|---|---|
| Задача | только ключ: `ABC-1` | куда списывать записи ниже, до следующей строки-задачи |
| Дата | только `ДД.ММ`: `19.10` | день, к которому относятся записи ниже |
| Запись | любой текст с длительностью | одна строка комментария worklog'а |
| Пустая | - | игнорируется |

**Длительность** пишется словами в любом месте строки: `1 час`, `2 часа`, `6 часов`, `30 минут`, `5 часов 30 минут`. Сокращения `ч` и `мин` тоже понимаются. Если на одну задачу за день набралось несколько записей, их длительности складываются.

**Год** бот подставляет сам: берёт тот, при котором дата ближе всего к сегодняшней. Например, `29.12` в посте от 2 января - это декабрь прошлого года. Дата в будущем считается ошибкой. В превью все даты показываются с годом.

**Что уходит в Jira:** на каждую пару "задача + дата" создаётся один worklog. Время worklog'а равно сумме длительностей. Комментарий - это строки записей, как они написаны в посте, через пустую строку. Время начала берётся из `JIRA_WORKLOG_START_TIME`. Ключи задач внутри текста записи (`XYZ-101:`) остаются просто текстом комментария.

### Ошибки формата

Бот покажет все ошибки сразу, с номерами строк, и ничего не отправит, пока они не исправлены:

- запись стоит до первой даты;
- в записи нет длительности, или часы (минуты) указаны дважды;
- дата не существует (`31.02`) или находится в будущем;
- одна и та же дата повторяется внутри одной задачи;
- за день по всем задачам набралось больше 24 часов.

Перед отправкой бот проверяет, что все задачи из поста существуют в Jira. Опечатка в ключе остановит отправку до того, как что-либо запишется.

## Запуск

Нужны Docker с Compose v2, make и Go версии из `go.mod` (если установлен более старый, `go` сам скачает нужный toolchain).

**1. Telegram.** Создай бота в [@BotFather](https://t.me/BotFather) и добавь его админом в канал с постами. Свой ID и ID канала можно узнать, например, у [@userinfobot](https://t.me/userinfobot) (для канала - переслав ему пост).

**2. Хранилище доступов - на своей машине, не на сервере.**

```bash
make vault ovpn=~/client.ovpn   # спросит URL Jira, логины, пароли, поля wa_*, маршруты и пароль-фразу
```

Получится `secrets/creds.age`, зашифрованный пароль-фразой. В нём всё корпоративное: URL Jira, логины и пароли Jira и VPN, поля `wa_*`, весь `.ovpn` и, если нужен, сертификат корпоративного CA. Маршрутом через VPN указывай только адрес Jira (`10.1.2.3/32`), а не всю корпоративную сеть. Пароль-фразу придумай длинную, не похожую на доменный пароль, и храни в менеджере паролей.

Без `ovpn=...` хранилище создаётся без VPN: так удобно, если бот запущен там, где корпоративный VPN уже включён.

**3. Сервер.**

```bash
cp .env.example .env              # заполни: ID в Telegram, задача по умолчанию, часовой пояс
make token                        # токен бота в secrets/telegram_bot_token, ввод без эха
scp secrets/creds.age server:...  # хранилище копируешь готовым, .ovpn на сервер не нужен
make up                           # соберёт образы, накатит миграции, запустит VPN-sidecar и бота
make logs
```

В `.env` только несекретные настройки, описание всех переменных - в [.env.example](.env.example). Файлы в `secrets/` должны принадлежать пользователю, под которым работают контейнеры, с правами `0400`; каталог - `0700` (`make secrets`).

**4.** Напиши боту `/start`, затем опубликуй или поправь пост недели в канале.

## Команды бота

| Команда | Что делает |
|---|---|
| `/status` | превью недели: часы по дням, норма по производственному календарю, что уже в Jira |
| `/submit` | превью с кнопками "Записать" и "Записать и на проверку" |
| `/settings` | напоминания: включить/выключить, пауза до завтра или на неделю |
| `/daily 19:30` | время ежедневного напоминания |
| `/weekly пт 16:00` | день и время недельного превью |
| `/vacation 27.10-31.10` | отпуск без напоминаний, `/vacation off` - отменить |
| `/cancel` | перестать ждать пароль-фразу |
| `/unlock` | снять блокировку после ошибки доступа |

Бот отвечает только владельцу (`TELEGRAM_OWNER_ID`) и только в личке. Обычный текст без команды он удаляет: вдруг это опоздавшая пароль-фраза.

## Команды make

`make` без аргументов показывает полный список.

| Команда | Что делает |
|---|---|
| `make secrets`, `make token`, `make vault ovpn=...` | каталог секретов, токен бота, хранилище доступов |
| `make up` / `make down` | поднять / остановить всё в Docker |
| `make logs`, `make ps` | логи бота и VPN-sidecar'а, статус контейнеров |
| `make run` | запустить бота локально, без Docker (переменные из `.env`) |
| `make test` | тесты |
| `make lint` | golangci-lint, собирается тем же Go, что указан в `go.mod` |
| `make fmt`, `make tidy` | форматирование, порядок в `go.mod` |
| `make migrate-up` | накатить новые миграции |
| `make migrate-down` | откатить последнюю миграцию |
| `make migrate-status` | какие миграции накатаны |
| `make migrate-new name=...` | создать новую миграцию |

dbmate для миграций запускается в контейнере, ставить его локально не нужно.

Локальный `make run` поднимает VPN только через sidecar, поэтому для запуска на своей машине удобнее хранилище без VPN (`make vault` без `ovpn=`) и включённый корпоративный VPN.

## Устройство

```
cmd/bot          - точка входа
cmd/vault        - создание зашифрованного хранилища доступов
internal/parser  - пост недели → worklog'и по парам "задача + дата"
internal/bot     - Telegram: канал, превью, кнопки, пароль-фраза, настройки
internal/notify  - когда напоминать (только по локальной базе)
internal/calendar - производственный календарь isdayoff.ru
internal/corp    - всё корпоративное: хранилище, VPN через sidecar, отправка
internal/jira    - клиент Jira и WorklogPRO
internal/store   - SQLite
docker/vpn       - VPN-sidecar: OpenVPN по запросу бота
```

Бот зависит от `internal/corp` только через интерфейс `bot.Runner`. Корпоративную часть можно вынести на отдельную машину (например, свой ноутбук), не переписывая бота.

## База данных

SQLite в `./data/bot.db`. Это один и тот же файл и для `make run`, и для Docker: каталог `./data` монтируется в контейнер. Контейнеры работают под твоим UID/GID, поэтому файлы в `./data` и `db/migrations` принадлежат тебе, а не root.

Схемой владеют миграции [dbmate](https://github.com/amacneil/dbmate) в [db/migrations](db/migrations). При `make up` сначала одноразовый сервис `migrate` накатывает миграции, и только после его успешного завершения стартует бот. Сам бот таблицы не создаёт: если миграции не накатаны, он сразу падает с подсказкой.

| Таблица | Что хранит |
|---|---|
| `users` | пользователи бота по Telegram ID |
| `user_settings` | настройки напоминаний (значения по умолчанию заданы в схеме) |
| `vacations` | отпуска, в которые напоминания не приходят |
| `week_posts` | недельные посты из канала в последней версии после правок |
| `submissions` | записанные worklog'и: задача, дата, длительность, ID worklog'а и периода WorklogPRO |
| `period_approvals` | периоды, отправленные на проверку |
| `notifications` | отправленные напоминания, чтобы после рестарта они не дублировались |

Все таблицы с самого начала привязаны к `user_id`, чтобы бот мог стать многопользовательским без переделки схемы.

### Правила миграций

- Новая миграция создаётся **только** через `make migrate-new name=add_something`. Время в имени файла dbmate ставит сам, всегда в UTC, поэтому порядок не зависит от часового пояса автора.
- Файлы миграций **не переименовываем**. Если миграция уже накатана, её не правим, а пишем новую.
- У каждой миграции должна быть рабочая секция `-- migrate:down`.
- Тесты пакета `internal/store` накатывают все миграции на временную базу, так что `make test` заодно проверяет схему.
